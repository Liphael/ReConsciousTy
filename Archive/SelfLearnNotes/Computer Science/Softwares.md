# Software Engineering



## Graphic API

A docking api between graphic engines and GPU drives.

图形 API（如 Vulkan、DirectX 12、OpenGL、Metal）本质上是**应用程序与 GPU/显卡驱动之间的编程接口**。它不直接“画图”，而是规定应用如何向 GPU 提交绘制、计算、内存和同步等命令。其核心功能可以概括为：

---

### 1. 初始化设备与查询能力
- 枚举 GPU、创建逻辑设备/上下文。
- 查询硬件能力：支持的格式、队列类型、着色器模型、扩展、显存类型等。
- 创建交换链/表面，与操作系统窗口系统对接。

### 2. 管理 GPU 资源
- 创建和管理缓冲区（顶点、索引、常量、存储缓冲）。
- 创建纹理、渲染目标、深度模板缓冲。
- 分配 GPU 内存、上传/回读数据。
- 管理资源布局、状态和生命周期。

### 3. 定义图形与计算管线
- 图形管线：顶点输入、图元装配、光栅化、深度/模板测试、混合、输出合并。
- 着色器：顶点、像素/片元、几何、细分、计算等着色器的编译、绑定与执行。
- 管线状态对象：混合、深度、光栅化、视口等状态配置。
- 计算管线：通用 GPU 计算、后处理、物理、AI 推理等。
- 现代 API 还支持光线追踪、网格着色器、可变速率着色等。

### 4. 录制和提交命令
- 创建命令缓冲/命令列表，录制绘制、计算、拷贝命令。
- 通过命令队列提交到 GPU 执行。
- 支持多线程录制，提高 CPU 端效率。
- 管理队列族、优先级和提交批次。

### 5. 同步与依赖管理
- 栅栏、信号量、事件、资源屏障。
- 管理 CPU-GPU、GPU-GPU、队列之间、渲染通道之间的依赖。
- 避免数据竞争，保证资源状态正确转换。

### 6. 呈现与帧管理
- 获取交换链图像、渲染到后缓冲、提交呈现。
- 管理双缓冲/三缓冲、垂直同步、帧延迟。
- 处理窗口缩放、全屏切换、HDR 输出等。

### 7. 描述符/绑定与状态管理
- 将纹理、缓冲区、采样器等资源绑定到着色器。
- Vulkan 使用描述符集/描述符池；DirectX 12 使用根签名/描述符堆。
- 管理管线布局和资源可见性。

### 8. 查询、调试与性能分析
- GPU 计时器、遮挡查询、管线统计。
- 验证层/调试层、错误检查。
- 与 RenderDoc、PIX、Nsight 等工具配合分析帧和性能。

### 9. 扩展与硬件特性暴露
- 通过扩展或功能等级暴露新硬件能力。
- 例如光线追踪、可变速率着色、采样器反馈、DirectStorage 等。
- 让应用在兼容性和性能之间做选择。

### 10. 计算与传输任务
- 图形 API 不仅用于渲染，也用于：
  - GPU 通用计算；
  - 图像/视频处理；
  - 数据压缩、物理模拟；
  - 机器学习推理；
  - 显存与系统内存之间的数据传输。

---

### 它和驱动、引擎的关系
- **图形 API**：规定“应用能调用哪些 GPU 功能、以什么方式调用”。
- **显卡驱动**：把 API 调用翻译成具体 GPU 硬件命令。
- **游戏引擎**：在图形 API 之上封装渲染管线、材质、光照、后处理等，让开发者不必直接写底层 API。

现代低级图形 API 的重要特点是：**减少驱动隐藏管理，把内存、同步、管线状态等责任交给应用**。因此功能上它提供的是“GPU 编程契约和工具集”，而不是自动帮你实现渲染效果。

一句话总结：**图形 API 的功能是让应用程序以标准化方式控制 GPU，完成资源管理、管线配置、命令提交、同步、呈现和计算，从而高效生成图像或执行并行计算。**
